# 任务系统规范（Task Vault v1）

> 人与 agent 共同遵守的任务系统操作规范。系统实现：Obsidian 插件 task-vault（~/workspace/task-vault）。
> 本文档是 FR-017 的交付物，同步镜像于 vault `02 Knowledge/任务系统规范.md`。生效日期：2026-08-19。

## 1. 数据模型

每个任务一个 md 文件，位于 `03 Tasks/<项目>/<年-月-日>/<slug>.md`（2026-08-19 定稿：项目在上、日期目录在下，**文件名/标题不带日期前缀**）。

目录规则：
- 项目文件夹 = frontmatter `project`（剥 wikilink）→ 无则看 `repo/*` 标签 → 都无进 `_未分类`
- 日期文件夹 = `created` 的 `YYYY-MM-DD`（创建日，稳定）
- 文件名 = 标题 slug（无日期）；同目录同名 → `-2`/`-3`
- 弹窗/捕获框改 `project` 字段 = **自动挪文件**（id/mirror 不动，身份不变）
- 历史日文件归档在 `03 Tasks/_archive/`，只读

归档（2026-08-20 收敛）：**任务文件不再归档、不再移动**——done/cancelled 就地保留在 03 Tasks/ 原位置，知识由「每日知识整理」cron（ce6091995d8f，03:30）提取（Daily Note + 02 Knowledge）。仅 7 天前的 AI 对话原始文件仍移入 `98 archive/`。

```yaml
---
id: <UUID>            # 身份，创建后永不改。任何字段编辑都不换身份
title: 任务标题
status: inbox         # 见 §2 状态机
start: 2026-08-20     # 可选。计划开始，未到不进"今天"
due: 2026-08-20T14:00 # DDL。date=全天；datetime=分钟级硬截止
remind: 30m           # 可选。提前量 m|h|d；默认 timed=due 时刻、全天=当天 09:00
created: 2026-08-19T10:00
started: 2026-08-19T14:32    # 首次进入 doing 自动记
completed: 2026-08-20T09:15  # 进入终态自动记
priority: high        # high | normal | low（只有三档）
source: hermes        # user | siri | hermes | cc | codex | lark | migration
assignee: user        # user(默认) | hermes | cc | codex
dispatched: 2026-08-19T14:35  # 上次派发时刻，agent 不手改
project: "[[magicedit]]"      # 可选 wikilink → 01 Projects
area: "[[学习]]"              # 可选 wikilink → 04 Areas
parent: <task-id>     # 可选。子任务指向父任务
blocked-by: [<task-id>]  # 可选。依赖列表；存在未终态依赖 → 显示态 blocked
tags: [watch]         # 业务标签自由
mirror:               # 同步器私有，人和 agent 禁碰
  reminders-uuid: ...
---
```

正文固定区块：`## 执行记录`（倒序时间线，最新在上，见 §4）、`## 委派`（委派指令全文，见 §5）。

## 2. 状态机（八态）

```
inbox ──→ todo ──→ doing ⇄ waiting
                    │  │     │
                    │  └──→ review ──→ done
                    └───────────→ cancelled（→todo 可重开）
review ──→ doing（退回返工）/ cancelled
blocked：非手设状态，由 blocked-by 推导显示；依赖全终态自动解除
```

| 状态 | 含义 | 图例 |
|---|---|---|
| inbox | 刚捕获未加工（无 due） | ○ 灰 |
| todo | 已排期 | ◻ 蓝 |
| doing | 进行中 | ◐ 绿 |
| review | 待用户复核 agent 交付 | 👁 紫 |
| waiting | 等外部（人/CI/上游） | ⏳ 黄 |
| blocked | 被依赖卡住（推导） | ⛔ 置灰 |
| done | 完成 | ✓ 暗淡 |
| cancelled | 取消但留痕 | ✕ 暗淡删除线 |

规则：done 无出口（不可误操作复活）；cancelled→todo 是唯一重开路径；DDL 到点只提醒报警，绝不自动改状态；过期任务不自动消失不顺延（顺延=显式改 due）。

**逾期处理铁律（2026-08-20 定，agent 侧）**：任何 cron / agent / 脚本**绝不修改非终态任务的 `due`**。夜间复盘/早上巡查遇到逾期未完成任务时：①只追加执行记录 `- HH:MM [hermes] [逾期] due <原due> 已过期未完成，排进今天`；②需要日历提醒就新建「(接力)」轻量任务（due=今天22:00，wikilink 原任务），原任务 due 原样保留。改 due 只发生在用户显式要求改期时。

## 3. 时间语义

- 侧边栏六分区实时推导：待复核（review，默认展开）/ 收件箱（inbox）/ 今天（start≤今天≤due 或当天到期）/ 过期（due<今天且未终态，红色置顶）/ 本周（due 在未来 7 天）/ 已完成（终态，默认折叠）
- 倒计时徽章：timed <24h 显示 `剩 XhYm`（琥珀，<1h 红）；超期显示 `超期 Xd/Xh`（红粗）
- 捕获框语法：`!high` `@project` `#tag` + 中文自然语言时间（`明天下午5点前`、`周五 14:00`、`8月25号`、`提前30分钟提醒`），解析失败原文进 inbox 不丢字

## 4. 写入协议（agent 版）

Agent（Hermes/CC/Codex）创建或更新任务 = 三步，不做别的：

1. **定标题**：简短动词短语（≤20 字，直说任务重心），例：「修 neutralizeFence 正则容错」「部署 PR #1139 到 dev」。项目归属写 frontmatter `project`（或 `repo/*` 标签），不在标题里堆上下文。
2. **改 frontmatter 字段**（原子写，改前重读）；完整背景/方案/引用原文写进正文 `## 任务描述` 区，标题保持简洁。
3. **写执行记录**（新条目插在区首，只插入，永不覆盖/改写历史行）。

**DDL 铁律（2026-08-19）：没有明确说明截止时间的任务，`due` = 当天 22:00（`YYYY-MM-DDT22:00`），绝不默认推到第二天。** 用户说"明天"才用明天；什么都不说就是今天 22 点。

执行记录格式（`## 执行记录` 区，**倒序：新条目插在最前面**；元信息一行、正文缩进两格、条目之间空一行）：

```
- YYYY-MM-DD HH:MM · `actor`                     # 普通进展
  内容

- YYYY-MM-DD HH:MM · **决策** · `actor`           # 关键取舍（归档会话会蒸馏进知识库）
  内容

- YYYY-MM-DD HH:MM · **评论** · `actor`           # 备注/上下文
  内容

- YYYY-MM-DD HH:MM · **卡点** · `actor`           # blocked/waiting 原因
  内容

- YYYY-MM-DD HH:MM · **todo→doing** · `actor`     # 状态迁移（含接单/终态）
  接单：…
```

actor = hermes | cc | codex | user。类型段可省（普通进展）。正文写清前因后果和被推翻的选项——
事后复核只看这里。接单必须落记录；`- YYYY-MM-DD HH:MM ` 这个前缀是承重的（兜底派发按它认条目边界），
别改成别的时间写法。

用户本人完成普通任务可走 done（触发总结 hook）；agent 任务遵守下述 review 门禁。

**承重前缀坑（08-23 实例）**：条目时间戳必须是空格分隔 `YYYY-MM-DD HH:MM`——`hermes-auto-update.py` 曾把 frontmatter 用的带 T 版（`2026-08-22T04:02`）同时写给条目行，`dispatch_backstop.py` 与插件 `agentProgress.ts` 两侧解析器都不认带 T 的行，导致该条目不被视为条目边界。写脚本的注意：frontmatter `created` 要 T、执行记录条目要空格，两个变量分开。

**聊天确认引用通道（FR-030a，2026-08-23 定）**：用户在聊天里明确批准收尾（如「做」「do」「确认」）时，agent 可据此直接写 done，但必须同时在执行记录里留可核验凭据——在 done 条目内（或时间上晚于 done 边的条目里）写引用行：

```
user-confirm: session=<会话id> msg=<消息id> quote="<用户原话子串>"
```

字段来源：Hermes 会话库的 messages 表（msg id、session id、原文、role=user）。插件门禁见此格式即放行；复核审计脚本（`scripts/review_audit.py`）会拿引用去会话库核验——msg 不存在 / role 非 user / quote 对不上 / 时间晚于 done / 系统注入消息（[ASYNC…、[OUT-OF-BAND…），任一不符按「agent 自行 done 未复核」告警。引用是承重结构，别改格式。

禁令：不碰 `mirror` 块；不改 `id`；不删除执行记录行；不手写 `dispatched`；不动 `03 Tasks/_archive/`；任何 agent actor（hermes/cc/codex）均不得将任务直接置 done，须走 review 待用户复核。

## 5. 委派协议

用户在详情弹窗选 agent + 填指令 → 系统写 `## 委派`（指令全文）+ assignee + dispatched → fire dispatch hook。

派发 hook（`~/.hermes/scripts/tv-dispatch-hook.sh`）按 assignee 起 agent：cc 走 `claude -p` 无人值守，
权限 = `--permission-mode acceptEdits` + 显式 `--allowedTools` 白名单（够读代码/改文件/跑测试/开 PR，
不含删除与部署）；白名单外的命令会被拒绝，agent 按第 5 条留卡点。会话输出落
`~/.hermes/cache/tv-dispatch/<task-id>.log`，退出码进 `tv-dispatch-hook.log`。
**不要改成交互式 `claude "<prompt>"`**：实测那样只把 prompt 预填进 TUI 不提交，进程 0% CPU 干等，
委派等于没发生（2026-08-19 实测两次）。

被委派的 agent 接手时：
1. 读任务文件全文（上下文都在：委派指令 + 执行记录时间线）
2. 落 `[todo→doing] 接单：…` 记录
3. 执行中即时插入记录（决策/卡点别攒到最后；写在区首）
4. 完成 → review，写 doing→review 迁移记录与交付摘要，停下等待用户复核；只有用户确认后才转 done
5. 做不完 → 留 `[卡点]` 记录 + 转 waiting，写清缺什么

兜底：派发后 30 分钟无接单记录，cron（`*/10`，`tv-dispatch-backstop.sh`）自动补派；显式 `#auto` 且 todo+assignee≠user 的任务即使无 dispatched 也会自动首派并写 dispatched。普通任务「有 assignee」仍不算派发过——`assignee` 常是创建时的默认归属。脚本在排他锁内最终重读并完整重判，hook 前先占用 ledger attempt，失败也计数。判据全文见 contracts §9。每任务最多补 3 次、单轮最多 3 个；人工重试 `python3 scripts/dispatch_backstop.py --force <任务文件>`。

### #auto 任务收尾规则

无论任务来源或委派方式，hermes/cc/codex 完成工作只能把 status 从 doing 置为 review，不可直接置 done。迁移记录正文必须附交付摘要：`做了什么 / 产出在哪 / 需要用户确认什么`。写完后停下等待用户复核；插件本地 UI 或 Reminders 勾选等 user 确认通道可从 review 转 done，需返工则转 doing。

## 6. Hook 体系

- **终态 hook**：status 进 done/cancelled 时 fire（幂等：每任务每终态恰好一次，ledger 落 `.taskvault/ledger.json`）。默认接归档总结管道。归档会话不轻信勾选状态，核执行证据（session 记录、产出 mtime）后才写归档。
- **派发 hook**：委派时 fire，参数含 TASK_ASSIGNEE。
- **手动总结**：弹窗"总结"按钮随时可触发，不占幂等名额。
- 配置：`.taskvault/config.json`（terminal_hook/dispatch_hook 命令模板，空=禁用；占位符 {TASK_*} + 环境变量 TV_TASK_*）。

## 7. Reminders 镜像

- 同步器（cron */5）：task.id ↔ Reminders UUID 稳定映射，双向完成回写；Siri/Reminders 新增自动回流为 inbox 任务（source:siri）
- 唯一清单「待办」；date due=全天提醒（默认 09:00 闹钟）、datetime due=定时提醒（due−remind 偏移）
- 手机上勾 Reminders = 完成任务（回写 + 补 fire 终态 hook）
- UTC 铁律：与 remindctl 交互的日期比较一律 +8h 后再取 date

## 8. 与旧系统的关系

- 旧文本行格式（`- [ ] 描述 #hermes 📅 日期`）已废弃；历史日文件归档于 `03 Tasks/_archive/` 只读
- `#hermes` 触发标签、ntfy→订阅器拉会话链路由终态 hook 取代
- Dashboard DQL 面板由侧边栏驾驶舱取代（Task Vault: Open / ribbon 图标）
- 旧 obsidian-reminders-sync 由新同步器取代
